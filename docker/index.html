Docker

Message Link Server with Docker

Docker Compose on any 64-bit x86 Linux computer that runs Docker.

There is one image with Chrome for Google Messages, Messenger, Google Voice and Instagram. Use latest; latest-google remains an alias for existing installs. Allow about 4 GB of memory.

Install

  1. Make its data folder, owned by the server's own account, 2787. The examples use /opt/messages-server; any folder works. You can choose a network share for backups on the server's page after installation.

    sudo mkdir -p /opt/messages-server/data
sudo chown 2787:2787 /opt/messages-server/data
sudo chmod 700 /opt/messages-server/data

  2. Make the keys volume. It holds the keys the data is sealed with, and lives inside Docker's own storage, away from your folders.

    docker volume create messages-server-keys
docker run --rm --user 0:0 --network none --entrypoint /bin/sh \
  -v messages-server-keys:/keys ghcr.io/wrenchware/messages-server:latest \
  -c "chown -R 2787:2787 /keys && chmod 700 /keys"

  3. Save this as compose.yaml in /opt/messages-server:

    name: messages-server
services:
  messages-server:
    image: ghcr.io/wrenchware/messages-server:latest
    container_name: messages-server
    user: "2787:2787"
    init: true
    environment:
      MESSAGES_DATA: /data
      MESSAGES_KEYS: /keys
      MESSAGES_RESTORE: "1"
      MESSAGES_ADMIN_PASSWORD: "${MESSAGES_ADMIN_PASSWORD:-}"
      MESSAGES_TAILNET: "${MESSAGES_TAILNET:-0}"
      MESSAGES_TAILNET_AUTHKEY: "${MESSAGES_TAILNET_AUTHKEY:-}"
      TZ: "${TZ:-Etc/UTC}"
    ports:
      - "${MESSAGES_BIND_IP:-0.0.0.0}:${MESSAGES_PORT:-8787}:8787"
    volumes:
      - "${MESSAGES_APPDATA}:/data"
      - "messages-server-keys:/keys"
    restart: unless-stopped
    stop_grace_period: 60s
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    mem_limit: 4g
    memswap_limit: 4g
    pids_limit: 2048
volumes:
  messages-server-keys:
    name: messages-server-keys
    external: true

  4. Save its settings as .env beside it, with your own address and time zone:

    MESSAGES_APPDATA=/opt/messages-server/data
MESSAGES_BIND_IP=192.168.1.20
MESSAGES_TAILNET=1
TZ=America/Chicago
    MESSAGES_BIND_IP
    The computer's address on your home network. Without it the port is published on every network the computer has, a VPN's included.
    MESSAGES_TAILNET
    1 puts the server on your Tailscale network, so your phone reaches it from anywhere. The page signs it in.
    MESSAGES_TAILNET_AUTHKEY
    Optional. A Tailscale auth key, for a computer you won't open a browser for. See Tailscale.
    MESSAGES_ADMIN_PASSWORD
    Optional. The server page's password, if you'd rather set it here than on the page.
    MESSAGES_PORT
    The port on this computer, 8787 by default.

  5. Start it and get the setup code:

    cd /opt/messages-server
docker compose up -d
docker compose logs messages-server | grep -i "setup code"

  6. Open the page, https://<this computer>:8787/, from a browser at home, and follow the first run.

Browser sign-in

The image includes Chrome. The current deployment settings enable its sign-in browser for all four services:

      MESSAGES_GOOGLE: "1"
      MESSAGES_GOOGLE_CHROME: "1"
      MESSAGES_CHROMIUM_HEADED: "1"
      MESSAGES_NETWORK_ISOLATED: "1"
      MESSAGES_CHROMIUM_NO_SANDBOX: "1"

The last one runs Chrome without its own sandbox, because a container with every capability dropped can't give Chrome one. The managed browser is restricted to the supported services' sign-in pages.

On the server's page

  1. Accept the certificate warning once: the server made its own certificate.
  2. Enter the setup code, then choose the page's password.
  3. If you have a backup, choose Restore from a backup on the first setup screen, before connecting accounts. Stop the old server first.
  4. Connect your accounts: Connect… beside each service.
  5. Sign the server in to Tailscale, and turn off key expiry.
  6. Set up notifications. A phone needs them before it can join.
  7. Add your phone: scan the code from your own server's page, check the server shown, then choose Join. Send a test notification once the phone is joined.
  8. Add a PC, then choose where backups go and their password.

Anyone with the page's password can manage the server. Joined phones and PCs read and send messages. To pick setup up later, choose Continue setup on the Overview. More about the first run.

Afterwards

Update
docker compose pull && docker compose up -d. The server comes back with the same sign-ins and devices.
Stop
docker compose down. It waits up to 60 seconds so pending sends finish.
Read the log
docker compose logs -f messages-server

Where things live

  • Keys: the messages-server-keys volume. Without it the data can't be read. It also holds the server's Tailscale identity.
  • Data: your data folder. Everything secret in it is sealed with the keys.
  • Backups: choose a network share on the server's page, with no Docker folder mapping. For local backups, create a separate host folder owned by 2787, map it to /backups, then select that path on the page. A backup holds your history and the server's identity, never a service sign-in.
