Message Link Server on Linux

A systemd service on Debian, Ubuntu, or a Linux container you made yourself. No Docker needed.

Not public yet. The package, messages-server-<version>-linux-x64.tar.gz, comes with the first public release. The steps below are how the install goes once it's out.

Before you start

  • A 64-bit x86 computer with systemd. Everything the server runs on is inside the package; the installer adds the few system libraries that are missing (ICU, OpenSSL 3, CA certificates, time zones).
  • For browser sign-in to any service: Debian or Ubuntu, and a kernel that lets ordinary accounts make user namespaces, which Google Chrome's sandbox is built from. On Ubuntu 24.04 and later that also means kernel.apparmor_restrict_unprivileged_userns set to 0.

Install

  1. Unpack the package and run its installer (put the version you downloaded in place of <version>):

    tar -xzf messages-server-<version>-linux-x64.tar.gz
sudo ./messages-server-<version>-linux-x64/install.sh --google

    Use --google to connect new accounts. It installs official Google Chrome and a virtual display; Messenger and Instagram sign-in need the browser too. On a plain Linux host, approve sign-in only if you trust its other users and programs. For an unattended install on a trusted host, use --google --allow-host-sign-in. Updates preserve the existing permission.

    It makes an account called messages-server, puts the program in /opt/messages-server and starts messages-server.service.

  2. Choose its settings in /etc/messages-server/environment, then restart it. Set the names first: they go into the certificate made the first time it starts.

    MESSAGES_HOSTNAMES=server.lan,192.168.1.20
MESSAGES_TAILNET=1
    sudo systemctl restart messages-server
    MESSAGES_HOSTNAMES
    The names and addresses your devices reach the server by, separated by commas.
    MESSAGES_TAILNET
    1 puts the server on your Tailscale network, so your phone reaches it from anywhere. The page signs it in.
    MESSAGES_TAILNET_AUTHKEY
    Optional. A Tailscale auth key, for a computer you won't open a browser for. See Tailscale.
    MESSAGES_PORT
    8787 by default. Allow it in your firewall for the home network only.
    MESSAGES_ADMIN_PASSWORD
    Optional. The page's password, if you'd rather set it here than on the page.

  3. Get the setup code from its log:

    sudo journalctl -u messages-server --no-pager | grep -i "setup code"

  4. Open the page, https://<this computer>:8787/, from a browser at home, and follow the first run.

On the server's page

  1. Accept the certificate warning once: the server made its own certificate.
  2. Enter the setup code, then choose the page's password.
  3. If you have a backup, restore it before connecting accounts. Stop the old server first.
  4. Sign in to your accounts from the server's page.
  5. Sign the server in to Tailscale.
  6. Set up notifications.
  7. Add your phone: scan the code from your own server's page, check the server shown, then choose Join. Send a test notification once the phone is joined.
  8. Add a PC, and set the backup password.

Anyone with the page's password can manage the server. Joined phones and PCs read and send messages. Setup steps can be picked up later from the page. More about the first run.

Afterwards

Update
Run a newer package's install.sh. The server stops (pending sends finish first), is replaced and starts again with the same sign-ins and devices. A nightly timer does this by itself once releases are published, and keeps Google Chrome up to date.
Read the log
sudo journalctl -u messages-server -f
Turn Google off again
Run install.sh --no-google.
Remove it
sudo /opt/messages-server/uninstall.sh removes the program and keeps your data, keys and backups. Add --all to remove those too (the backups stay unless you also add --backups).

Where things live

  • /var/lib/messages-server/keys: the keys the data is sealed with, Google's Chrome profile and the server's Tailscale identity.
  • /var/lib/messages-server/data: sign-ins, devices and history, sealed with the keys, and the server's log.
  • /var/lib/messages-server/backups: the server's own backups, one encrypted file a day. A backup holds your history and the server's identity, never a service sign-in.

The service runs with no privileges and can write only its own folder. It's limited to 2 GB of memory, or 4 GB with Google.
