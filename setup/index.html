Choose your setup

Message Link works three ways. Pick the one that matches what you have.

Just a Windows PC

Message Link starts its own server on this PC. Connect your accounts on the server's page. The app keeps working in the system tray while the PC is on and shows notifications as messages arrive.

You can also connect this PC to a server you already have.

Read the Windows guide

A Windows PC and a phone

Message Link Server starts when you sign in to Windows. Your phone uses the accounts connected on that PC, which must stay on and signed in for the phone to get messages.

Set up Tailscale on the server's page before adding a phone or another PC.

Read the Windows guide

A home server and a phone

Message Link Server runs on a computer that's always on. Your phone and every PC with Message Link use the accounts signed in on it. Each one is set up from a computer with a web browser; the server has a page of its own that walks you through it.

What the server needs

  • A 64-bit x86 computer that stays on. ARM boards like the Raspberry Pi aren't supported.
  • Allow about 4 GB of memory for the server and its sign-in browser. The Docker image includes Chrome for all four services.
  • One port on your home network, 8787 by default. Nothing needs opening to the internet.
  • A free Tailscale account, so your phone can reach the server away from home.
  • A Google account for a free Firebase project, if you want notifications on your phone.
  • A backup destination separate from the server's data. Configure it on the server's Backups page.

The server's first run

Every install ends the same way: at the server's own page, https://<your server>:8787/, opened in a browser on your home network.

Anyone with this page's password can manage the server. Phones and PCs that join can read and send messages.

Have a backup? Restore it before connecting accounts. Stop the old server first.

  1. Accept the certificate warning once. The server made its own certificate, so your browser doesn't know it yet. To be thorough, compare the certificate's SHA-256 fingerprint in the browser with the tls fingerprint line in the server's log.
  2. Enter the setup code. The server prints it in its log the first time it starts. Each guide shows where to find it.
  3. Choose the page's password. 12 characters or more, and one you use nowhere else. The page asks for it again before anything that matters, like adding a device.
  4. Follow the steps. One screen each, and you can skip any of them. A checklist on the page's front keeps whatever is left, and each card reopens its own step.
    • Your accounts: sign in to each service from the server's page.
    • Tailscale: sign the server in, so your phone reaches it from anywhere. Learn more.
    • Notifications: give the server your Firebase project. After joining your phone, send it a test notification. Learn more.
    • Add a phone: the page shows a code. In Message Link on the phone, choose I have a server, then Scan your server's code. Check the server shown, then choose Join.
    • Add a PC: the page shows one line to paste into Message Link for Windows, under Settings, Connections, Server.
    • Backups: choose a folder or network share and set the password backups are sealed with. If you lose that password, nobody can open those backups, the server included. Learn more.

Manage accounts and joined devices on the server's page. Joining a phone or PC does not give it administration rights.

Choose where backups go

On the server's Backups page, choose a folder or Network share (SMB). For a share, enter the file server, share name, optional subfolder and sign-in. Create the subfolder first, then choose Check and use share. No Docker folder mapping is needed.

A local folder must be outside the server's data and keys. With Docker, use a mapped folder: files inside the container are lost when it is replaced. Keep backups on separate storage if you want to recover after the server's disk fails.

The share password and backup password are separate. The server keeps the share sign-in protected; backups never include it or your services' sign-ins. A partial backup missing Messenger history is kept with a warning and does not count as a new successful backup. If a share refuses sign-in, enter its credentials again before backups can resume.

Restore a backup

Stop the old server first. On a new server, choose Restore from a backup before connecting accounts. Choose the folder or share holding the file, enter the backup password, and review the devices and any missing-history warning. Sign in to each service again after restoring.

The server page's saved password returns to the one in the backup. Use that password after the restart. A password set in the server's installation settings stays as it is.
