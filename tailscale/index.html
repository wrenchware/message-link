Reaching your server from anywhere

Your phone reaches your Messages Server through Tailscale, at home or away, without opening anything on your router to the internet.

What Tailscale is for

Tailscale makes a private network of your own devices, wherever they are. Messages Server joins it as a machine of its own, called messages-server, and Messages on your phone joins it too. Only devices signed in to your Tailscale account get through, and the server still asks each one to prove it was added.

  • A free personal Tailscale account is enough.
  • Messages runs Tailscale itself on the phone. You don't need the Tailscale app there.
  • Nothing on the computer the server runs on changes. If it already has Tailscale, that stays as it is.
  • Tailscale's own logging is turned off in the server and the phone: nothing about your network is uploaded.

On the server's page

The Tailscale step of the server's first run, and its card on the page's front afterwards, walk you through this. Each line has a link straight to the right page of Tailscale's admin console, and a tick appears by itself once the server sees it done.

  1. Sign in to Tailscale. Choose Sign in to Tailscale and sign in with your own account. The same link is shown as a code too, if signing in on your phone is handier. The step turns green by itself.

  2. Approve it, if your Tailscale network asks for new devices to be approved. The page links to the machine.

  3. Turn off key expiry for the server. Otherwise Tailscale signs it out after 180 days. The page lists each Messages phone too, so you can do the same for them.

  4. Only your devices can reach the server. If you're the only person on your Tailscale network, this is already done, and the page says why. If others share it, the page shows the rule that keeps them out.

  5. Tailnet Lock, only if your network uses it: the server has to be signed from one of your signing devices. Show the command gives you the line to run there.

Fix it for me

Rather not click through Tailscale's console? Fix it for me lets the server do the steps above itself.

  1. In Tailscale's admin console, make an OAuth client under Settings. The page says which permissions to give it, with a link.
  2. Paste the client's ID and secret into the page, once.
  3. The server turns off key expiry for itself and each Messages phone, approves them if your network needs approval, and adds the access rule. It tells you what it changed.

It never touches Tailnet Lock: signing stays on your own trusted device. You can remove the OAuth client on the page at any time, and it's never put in a backup.

On your phone

  • Joining a server signs the phone in to Tailscale first. The sign-in opens in a browser tab and comes back to Messages by itself.
  • Sign in with the same Tailscale account as the server. If the phone is signed in as someone else, Messages says so by name before it asks to join.
  • In Messages' Settings, the Tailscale section shows the account, the phone's name on your network, whether it reaches the server directly or through Tailscale's relays, and its key expiry. Sign out and Use another account are there too.

When something changes

  • Tailscale signed the server out. The page says so with a Sign in again button. No restart needed.
  • A different Tailscale account. Use another Tailscale account on the page signs the server out and forgets its Tailscale identity, so it can join another network.
  • A PC away from home. A PC with the Tailscale app can use the server's Tailscale name, messages-server, as its address.
  • New hardware. Remove the old machine in Tailscale's console before the new server signs in, or the new one is named messages-server-1 and your phone won't find it by name.

Without a browser at hand

For a server you set up from a script and won't open a page for, give it a Tailscale auth key instead of the sign-in link. Make one in Tailscale's admin console under Settings, Keys, Generate auth key, and put it in the server's settings (MESSAGES_TAILNET_AUTHKEY, or the auth key field or question in your host's guide). The server uses it only to sign in the first time; clear it afterwards.

Use a key without tags. A tagged key makes a tagged machine, and the server then can't tell which person owns it. Instead of letting in only your devices, it lets in every device your access rules allow.
