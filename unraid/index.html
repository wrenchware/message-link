Message Link Server on Unraid

A container on your Unraid server, installed from Community Applications.

Not public yet. The image isn't available to pull, and Message Link Server isn't listed in Community Applications yet. The steps below are how the install goes once it is.

Before you start

  • Unraid with Docker turned on.
  • A network share for the server's daily backups, chosen later on its page. A share on this Unraid server works.
  • About 4 GB of memory for the container. The server's Chrome browser handles new sign-ins for all four services.

Install

  1. Set Docker's stop timeout. In Settings › Docker, set Docker Stop Timeout to at least 60 seconds, then Apply. Messages that are being sent can then finish when the container stops.

  2. Find it in Apps. Search for Message Link Server and choose Install.

  3. Check the fields. The defaults suit most servers:

    Port
    8787. The Message Link apps and the server's page both use it.
    Reach from your tailnet
    1, so your phone reaches the server from anywhere through Tailscale. The server's page signs it in.

    Under Show more settings there are a few you can leave alone: a Tailscale auth key for signing in without a browser (see Tailscale), the Server page password if you'd rather set it here than on the page, and Google Messages and Voice, which is on.

  4. Apply.

  5. Get the setup code. On the Docker tab, click the container's icon and choose Logs, or in the terminal:

    docker logs messages-server 2>&1 | grep -i "setup code"

  6. Open the page. The container's icon, WebUI, or https://<your server>:8787/. Then follow the first run.

On the server's page

  1. Accept the certificate warning once: the server made its own certificate.
  2. Enter the setup code, then choose the page's password.
  3. If you have a backup, choose Restore from a backup on the first setup screen, before connecting accounts. Stop the old server first.
  4. Connect your accounts: Connect… beside each service.
  5. Sign the server in to Tailscale, and turn off key expiry.
  6. Set up notifications. A phone needs them before it can join.
  7. Add your phone: scan the code from your own server's page, check the server shown, then choose Join. Send a test notification once the phone is joined.
  8. Add a PC, then choose where backups go and their password.

Anyone with the page's password can manage the server. Joined phones and PCs read and send messages. To pick setup up later, choose Continue setup on the Overview. More about the first run.

Updates

In Auto Update Applications, turn on messages-server in the nightly schedule and set its Docker stop timeout/delay to at least 60 seconds as well. The plugin uses its own shorter timeout otherwise. An update restarts the server with the same sign-ins and devices.

Where things live

  • Keys: a Docker volume, messages-server-keys, inside Docker's own storage and outside every share. It holds the keys the data is sealed with and the server's Tailscale identity.
  • Data: a Docker volume, messages-server-data, beside the keys in Docker's own storage: sign-ins, history and devices. Everything secret in it is sealed, so a copy of it alone is useless. Leave room in Docker's storage for your history.
  • Backups: the network share you choose on the server's page. A backup holds your history and the server's identity, never a service sign-in. After restoring one you sign in to each account again, and your devices stay joined.

Recreating Docker's image file (docker.img) deletes both volumes: the data and the keys it is sealed with. The server's own backups are how you come back from that: restore one on the page of a fresh server.

Good to know

  • Keep the port on your home network. To reach the server away from home, use its Tailscale door rather than publishing the port on Unraid's own Tailscale.
  • The server's Google Chrome runs every page in Chrome's sandbox. For that, the container runs without Docker's default system call filter (seccomp=unconfined). It still runs as its own user, with every capability dropped.
  • Stop it from the Docker tab, or with docker stop -t 60 messages-server, so pending sends finish.
