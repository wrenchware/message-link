Messages Server on Unraid

A container on your Unraid server, installed from Community Applications.

Not public yet. The image isn't available to pull, and Messages Server isn't listed in Community Applications yet. The steps below are how the install goes once it is.

Before you start

  • Unraid with Docker turned on.
  • A backups share, or another share for the server's backups. The default is /mnt/user/backups/messages.
  • About 4 GB of memory for the container. Google Messages and Google Voice run beside the server's own Google Chrome.

Install

  1. Make the two folders first. The server runs as its own account, 2787, which nothing else on Unraid uses. Docker would make missing folders owned by root, and the server would refuse to start. In Unraid's terminal:

    mkdir -p /mnt/user/appdata/messages-server /mnt/user/backups/messages
chown 2787:2787 /mnt/user/appdata/messages-server /mnt/user/backups/messages
chmod 700 /mnt/user/appdata/messages-server /mnt/user/backups/messages

  2. Find it in Apps. Search for Messages Server and choose Install.

  3. Check the fields. The defaults suit most servers:

    Port
    8787. The Messages apps and the server's page both use it.
    Data
    /mnt/user/appdata/messages-server. Sign-ins, history and devices, sealed with keys kept elsewhere.
    Backups
    /mnt/user/backups/messages. One encrypted file a day.
    Reach from your tailnet
    1, so your phone reaches the server from anywhere through Tailscale. The server's page signs it in.

    Under Show more settings there are a few you can leave alone: a Tailscale auth key for signing in without a browser (see Tailscale), the Server page password if you'd rather set it here than on the page, and Google Messages and Voice, which is on.

  4. Apply. Then set Docker's stop timeout for this container to at least 60 seconds, so messages that are being sent can finish when it stops.

  5. Get the setup code. On the Docker tab, click the container's icon and choose Logs, or in the terminal:

    docker logs messages-server 2>&1 | grep -i "setup code"

  6. Open the page. The container's icon, WebUI, or https://<your server>:8787/. Then follow the first run.

On the server's page

  1. Accept the certificate warning once: the server made its own certificate.
  2. Enter the setup code, then choose the page's password.
  3. Sign the server in to Tailscale.
  4. Sign in to your accounts in the server's browser, on the page.
  5. Add your phone: scan the code the page shows, from Messages on the phone.
  6. Turn on notifications and send a test to your phone.
  7. Add a PC, and set the backup password.

Every step can be skipped and picked up later from the page's front. More about the first run.

Updates

In Auto Update Applications, turn on messages-server in the nightly schedule and set Docker stop timeout/delay to at least 60 seconds. The plugin uses its own shorter timeout otherwise. An update restarts the server with the same sign-ins and devices.

Where things live

  • Keys: a Docker volume, messages-server-keys, inside Docker's own storage and outside every share. It holds the keys the data is sealed with and the server's Tailscale identity.
  • Data: the appdata folder. Everything secret in it is sealed, so a copy of it alone is useless.
  • Backups: the backups folder. A backup holds your history and the server's identity, never a service sign-in. After restoring one you sign in to each account again, and your devices stay joined.

Recreating Docker's image file (docker.img) deletes the keys volume, and the data can't be read without it. The server's own backups are how you come back from that: restore one on the page of a fresh server.

Good to know

  • Keep the port on your home network. To reach the server away from home, use its Tailscale door rather than publishing the port on Unraid's own Tailscale.
  • The template runs Google Chrome without its own sandbox, because a container with every capability dropped can't give Chrome one. Chrome only ever loads Google's sign-in pages.
  • Stop it from the Docker tab, or with docker stop -t 60 messages-server, so pending sends finish.
